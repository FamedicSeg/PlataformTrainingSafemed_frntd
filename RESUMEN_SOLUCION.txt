PROBLEMA ENCONTRADO:
────────────────────────────────────────────────────────────────────────────────
Los cursos se estaban guardando y mostrando como "expirados" incorrectamente
porque el frontend usaba esta comparación frágil:

    const esCursoExpirado = (cap) => {
      return new Date() > new Date(cap.fecha_fin_curso);  // ❌ Problema aquí
    };

Cuando el backend devolvía fechas en formato ISO-8601 (ej: "2024-12-31T23:59:59Z"),
JavaScript a veces parsea estas strings incorrectamente, causando que se interprete
como una fecha muy antigua (1970) o como "Invalid Date".


SOLUCIÓN IMPLEMENTADA:
────────────────────────────────────────────────────────────────────────────────
Se creó un módulo de utilidades robustas: src/utils/dateUtils.js

Funciones principales:

  ✓ parseFecha(dateStr)
    → Parsea cualquier formato de fecha de forma segura
    → Maneja: ISO-8601, timestamps, objetos Date
    → Valida que la fecha sea válida antes de devolverla
    → Retorna null si es inválida (con logging de advertencia)

  ✓ esCursoExpiradoSeguro(fechaFin)
    → Reemplaza la lógica anterior
    → Usa parseFecha para validar primero
    → Compara de forma segura

  ✓ esCursoProximoSeguro(fechaInicio)
    → Verifica si un curso aún no ha iniciado
    → Usa la misma lógica robusta de parseo

  ✓ formatearFecha(dateStr, conHora)
    → Formatea fechas consistentemente (locale es-EC)
    → Útil para mostrar al usuario

  ✓ tiempoRestante(fechaFin)
    → Calcula días/horas/minutos hasta expiración
    → Útil para mostrar "expira en X días"

CAMBIOS EN EL CÓDIGO:
────────────────────────────────────────────────────────────────────────────────
ANTES (❌ Frágil):
  const esCursoExpirado = (cap) => {
    if (!cap.fecha_fin_curso) return false;
    return new Date() > new Date(cap.fecha_fin_curso);  // Puede fallar
  };

DESPUÉS (✅ Robusto):
  import { esCursoExpiradoSeguro } from '../utils/dateUtils';
  
  const esCursoExpirado = (cap) => {
    return esCursoExpiradoSeguro(cap.fecha_fin_curso);  // Seguro
  };
